Agent prompts

A catalog of the agent roles that planned, built, checked and ran the study, with the prompts each one received, lightly edited for privacy.

Every experiment on this site was run by AI agents: Claude Code sessions working under James Barnes’s direction. A lead session wrote a prompt for each subagent, launched it and read its short report. These pages publish those prompts, so you can see exactly what each agent was told and reuse the roles. Numbers such as 03 or 115 give each prompt’s position in the order the prompts were sent. Terms are defined in the glossary.

How the prompts were edited

Prompts are shown as sent, with these edits:

  • Absolute paths are replaced: <repo> is the repository root and <home> a home directory.
  • Where a prompt said where an API key is kept, it now reads “your API key (loaded from an env file; never printed)”.
  • Sentences about other work running on the study machine, about other local sessions, and machine-specific process advice are removed. “The RunPod account is shared with other sessions” becomes “if your GPU account is shared, only touch pods you created”.
  • Context and steps about a private document are replaced with neutral wording or removed. The one removed step is marked in place.
  • The email address in the commit trailer is shortened.

Goals, design, rules, deliverables, budget caps and stop rules are unchanged.

Withheld: prompts for planted test items

Phases 1 and 1b tested the cheap score on planted items: short passages that agents wrote in the voices of real authors and inserted into copies of those authors’ public research records. The prompts for those writers, judges and adjudicators (37 to 78, and 88 to 101) are not published. Neither are the templates they followed (prompts/write_*.md, prompts/rewrite_d4.md, prompts/judge.md and prompts/adjudicate.md). This keeps text written in real authors’ voices from circulating. The design is described in the Phase 1 briefing.

How the prompts were written#

The prompts share a few habits that are worth copying.

  • Role first. Each opens with the agent’s role, the date and where the task sits in the study.
  • A read-first list. The exact files to read, with the authority named: the frozen pre-registration, BUILD.md or the latest report.
  • Ownership. The files the agent may write. Everything else is read-only.
  • Exact deliverables. Paths, formats, and the rule that anything committed holds numbers only.
  • Hard rules. Privacy; downloads treated as untrusted and read with python -I; commits of explicit paths only, never git add -A; LF line endings; tests before committing.
  • A budget. A hard cap, a cost estimate before each paid stage, and “stop and report” rather than exceed it.
  • Ambiguity. Write the question down instead of improvising an analytic choice.
  • Refusals. If a writer or a safety classifier declines, do not reword, reroute or reassign the task; report it.
  • Short replies. A reply of 12 lines or fewer, or one status line, so the lead’s context stays small.
