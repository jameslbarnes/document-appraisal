Phase 1b builder prompts

The prompts for the two builders who set up the Phase 1b gate analysis and the 13B learning test.

Phase 1b reran the planted test with larger scorers, OLMo-2-13B and OLMo-2-32B, on fresh items. Because the 13B passed, Phase 1b then tested whether the 13B’s score predicts what the 13B actually learns from real research records (H1b). Two builder prompts set up the code. The writers, judges and adjudicators who made the fresh planted items are withheld; the catalog page explains why, and how the prompts shown here were edited.

86 · Builder: the Phase 1b gate analysis and checks#

Launched 2026-10-19 13:47 UTC. What it did. Built three new pieces without changing frozen code: the gate analysis at 97.5% intervals, reusing the Phase 1 resampling (scripts/run_g1b.py); a paired relatedness parity check with rewrite and drop rounds (src/cpappraise/plant/t16p.py, scripts/t16p.py); and a flag that builds items without counterfactual variants. What it produced. Those modules, with tests. The gate then passed for the 13B, whose score ranked the planted finding above its same-story control in 95% of items, 19 points better than word overlap. It failed for the 32B. See the briefing.

You are a builder on the compression-progress appraisal study, working in <repo> (Windows; Python at .venv\Scripts\python.exe; the package `cpappraise` is installed editable). Read BUILD.md (rules: privacy, explicit-path commits, LF endings, tests before commit) and PREREG_1B.md (Phase 1b draft r2; §3 "T16p", §5 analysis, §3 CF).

Build three pieces of Phase 1b code. These are NEW modules or flags. Do NOT change the behaviour of frozen modules (analysis/q1.py, evaluate.py, baselines.py, plant/t16.py, jobs.py, ...); import from them.

1. `scripts/run_g1b.py`: the G1b analysis per scorer, PREREG_1B §5.
   - Reuse the frozen Q1 machinery: `analysis.q1.load_table`, the `ClusterResampler` from `evaluate`, `evaluate_contrast`, and the baseline-vs-method paired-difference construction that q1 uses for `baselines_vs_method`. The point is the SAME resamples as q1, with intervals computed at level 0.975 via `evaluate.percentile_ci(level=0.975)` / `one_sided_lb`.
   - Inputs:
     - the variants (valid items) and the planted rows (`planted.json`) of one scorer;
     - the θ artifact; the T16 outcome JSON (for J4);
     - baseline rows (computed like `scripts/run_q1.py` does: `baselines.planted_baseline_rows` with the pinned encoders. Reuse run_q1's functions, and `--reuse-baselines` to skip recomputation);
     - optionally a second scored dir with Phase 1's C items for T3 (32B), or `--t3-known <q1.json path>` to quote a known T3 (13B: runs/Q1_13b/q1.json), labelled "known before freeze".
   - Output, numbers only, via privacy.write_json:
     - T1 (AUROC seminal vs noise; ≥ 0.85 and LB97.5 ≥ 0.75);
     - T2 (paired W seminal vs NI-s; ≥ 0.85 and LB97.5 ≥ 0.75; J4: if the T16 status is FAILED with a forward or held-out failure, also require the one-sided 97.5% LB of C2u > 0.50);
     - T2w (d = W(P_corr) − W(B9-lex) on C2 from the same paired resamples; LB97.5 > 0);
     - T3 (FP_raw ≥ 0.30 and FP_corr ≤ 0.5·FP_raw, with 97.5% intervals);
     - G1b = T1 ∧ T2 ∧ T2w ∧ T3;
     - M1b (d_b for B9-lex, B9-emb, B9-emb2, B10: PASS iff all d_b ≥ 0.05 with LB > 0; FAIL iff some UB < 0.05; else INCONCLUSIVE);
     - C3b only if CF rows exist (W seminal vs CF ≥ 0.85, LB97.5 ≥ 0.75), plus the descriptive C2 unpaired, C2e, C2u and calibration lines.
   - Tests in tests/test_run_g1b.py, using tests/test_q1.py's `make_world` synthetic generator: a passing world, a world failing T2w (a baseline as good as the method), CF absent, the known-T3 path, and a check that 97.5% intervals are wider than q1's 95% ones on the same data.

2. `src/cpappraise/plant/t16p.py` plus a CLI subcommand script (`scripts/t16p.py`, so plant/cli.py stays unchanged): the paired relatedness parity check, PREREG_1B §3.
   - Reuse `plant.t16`'s detector scoring (`score(...)` with `Detectors.pinned`, the same items as `cli.t16_items`).
   - For each of B9-lex, B9-emb, B9-emb2, B10, compute the paired win rate W_d = mean over test items of [score_d(seminal) > score_d(NI-s)], ties 0.5. Pass iff every W_d ∈ [0.35, 0.65].
   - It is a resumable state machine like t16's:
     - fail with < 2 completed rounds → request rewrites for the top 25% (ceil) of items by mean standardized within-item gap (per detector: the gap divided by its SD over items, ddof 1; mean over the four detectors; signed toward the failure);
     - write `rewrite_round<r>.json` as {item_id: "closer"|"further"}, in the format `authoring build-d4-rewrite --directions` reads ("closer" when the item's gap favours seminal);
     - after 2 rounds → drop items in descending gap order while failing and more than 60 test items remain → PASS / PASS_AFTER_DROPS / FAILED;
     - write the state, a drops file and a numbers-only outcome JSON.
   - Tests with synthetic detector scores.

3. A `--no-cf` flag for `plant build`.
   - Add `BuildInputs.no_cf` (default False), so CF variants are not generated or written. Keep every other check. If the f′-dependent checks must be skipped, document which.
   - Wire the CLI flag into plant/cli.py's build parser. This is a small additive change: the existing behaviour is unchanged when the flag is absent, and it mirrors the existing `--no-fab`.
   - Add a test in tests/test_plant_build.py next to `test_no_fab_builds_f_items_without_fab_inserts`.

102 · Builder: the 13B learning test (H1b)#

Launched 2026-10-20 00:15 UTC. What it did. Prepared the 13B fine-tuning config, with gradient checkpointing so the 13B fits on one GPU; the H1b runner around the frozen analysis, with a loud check for a known column-name trap; and the lane configs. It launched nothing, so the lead could tag the code before any data were scored. What it produced. configs/finetune_pilot_13b.json, scripts/run_h1b.py and configs/lane_h1b_*.json. The test then failed its bar: the score’s correlation with the 13B’s measured learning gain was 0.278 (0.154 to 0.388) against 0.50, and a simple in-context baseline did better (0.442). See the briefing.
